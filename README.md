# YOMIKAZE

**Read. Discover. Escape.**

A modern **Manga + Manhua** discovery and online reading platform — zero budget, zero paid APIs, fully legal content.

## ✨ Features

- **Discover** — trending, popular, and latest-update rails on the home page
- **Manga / Manhua / Manhwa libraries** — search, genre, status & year filters, 4 sort modes, load-more pagination
- **Real search** — debounced, searches title, alternative title, author and genre
- **Title details** — cover, banner, description, stats, genres, and full chapter list
- **Reader** — single-page & vertical modes, fit-width/fit-height, fullscreen, keyboard navigation, swipe, page progress, previous/next chapter
- **Continue reading** — resume exactly where you stopped
- **Favorites & History** — stored locally in `localStorage`
- **Dark / Light theme** — defaults to dark, persisted
- **Error & loading states everywhere** — skeletons, retry buttons, no blank screens
- **SEO** — dynamic titles, meta descriptions, Open Graph tags
- **Mobile-first** — bottom tab bar, touch controls, no horizontal overflow

## 🔌 Content providers

YOMIKAZE uses a strict **provider architecture**. The UI never talks to provider APIs directly — everything flows through the `ContentProvider` interface (`src/providers/ContentProvider.ts`).

| Provider | Source | Content |
|---|---|---|
| `mangadex` **(default)** | [MangaDex official API](https://api.mangadex.org) — free public REST API, no key, CORS-enabled | **Real metadata + REAL chapter pages** (At-Home servers). Full search, genres, trending/popular/latest, covers |
| `auto` | MangaDex + demo merged | Real chapters with an always-working offline fallback |
| `anilist` | [AniList GraphQL](https://docs.anilist.co/) | Real metadata only (no readable chapters) |
| `demo` | **Original YOMIKAZE artwork** (generated by `scripts/generate-demo-pages.mjs`) | 3 demo titles × 3 chapters × 6 pages — fully functional reader, clearly labeled `Demo Reader` |
| `mock` | Built-in data | Offline metadata for network-free testing |

`VITE_CONTENT_PROVIDER` switches between them (default `mangadex`).

> **Legal note:** YOMIKAZE does not scrape unauthorized manga sites or rehost copyrighted scans. Chapters come from MangaDex's official API (credit to MangaDex and the scanlation groups is shown in the footer and reader). Demo chapters use only original artwork.

## 🤖 JUKU scraping engine (`juku/`)

**JUKU** is YOMIKAZE's permanent, unified production scraping engine (Node +
TypeScript). It follows the JUKU mandatory toolchain spec — every component
below is real, wired together, and used by the actual scraping pipeline:

| Component | Implementation |
|---|---|
| HTTP client | **Axios** (fast direct requests) — `juku/src/http.ts` |
| Browser automation | **Playwright** (JS-rendered pages, system Chrome) — `juku/src/browser.ts` |
| HTML parser | **Cheerio** — `juku/src/html.ts` |
| Proxy pool | `ProxyPool` — rotation, health checks, latency, cooldown, auto-recovery — `juku/src/proxies.ts` |
| Existing proxies | Auto-loads `proxy_checker/working_proxies.txt` + `scraper/working proxies/*.txt` (HTTP/HTTPS/SOCKS4/5, auth, legacy `ip:port:user:pass`) |
| Request queue | Priority queue, per-source limits, timeouts, dedup, retry queue — `juku/src/queue.ts` |
| Retry manager | Exponential backoff (network / timeout / 429 / 5xx / proxy) — `juku/src/retry.ts` |
| Rate limiter | Per-source rps / rpm / concurrency — `juku/src/ratelimit.ts` |
| Network observer | Playwright response capture (fetch/XHR/JSON/HTML, chapter/page data) — `juku/src/browser.ts` |
| Cache | TTL, URL keys, request dedup, invalidation, persistent — `juku/src/cache.ts` |
| Deduplication | requests / jobs / anime / chapters / pages / URLs — `juku/src/dedup.ts` |
| Normalizer | Source results → Juku common schema (title, alternativeTitles, slug, description, cover, author, artist, genres, status, rating, source, sourceUrl, chapters, chapterNumber, chapterTitle, chapterUrl, pages, pageNumber, imageUrl) — `juku/src/normalizer.ts` |
| Source adapters | `SourceAdapter` interface + registry: `search / getDetails / getChapters / getChapterPages / getLatest / getPopular` — `juku/src/sources/` (MangaDex, MangaFire, MangaKakalot, Local JSON). Browser adapters rotate proxies + detect WAF/Cloudflare challenges automatically |
| Image/page extractor | Ordered pages, URL normalization, tracking-param stripping — `juku/src/extractor.ts` |
| Scheduler | Latest updates, chapter checking, metadata refresh, source health checks — `juku/src/scheduler.ts` |
| Structured logger | source, url, jobId, duration, status, retry, success/failure, errors, chapters/pages found; secrets redacted — `juku/src/logger.ts` |
| Circuit breaker | Disables failing sources, cooldown, automatic test/recovery — `juku/src/circuit.ts` |
| Database writer | Central upserts (anime/chapter/page), dedup, source relationships, last successful scrape, errors, timestamps — `juku/src/db.ts` |

**Execution flows** (as specified):

```
Normal page:  Proxy Pool → Rate Limiter → Request Queue → Axios → Cache → Cheerio → Normalizer → Dedup → Database
JS page:      Proxy Pool → Rate Limiter → Request Queue → Playwright → Network Observer → Cheerio/JSON → Normalizer → Dedup → Database
Failures:     Request → Retry Manager → Proxy Rotation → Request again
Repeated failures: Circuit Breaker → Cooldown → Health Check → Automatic recovery
```

**CLI** (`npm run juku -- <command>`):

```bash
npm run juku -- search "one punch man"          # search MangaDex
npm run juku -- import --rail latest --limit 10 --chapters latest-20
npm run juku -- import --rail popular --limit 20 --chapters all
npm run juku -- update                          # fetch new chapters for existing titles
npm run juku -- auto --once                     # auto-import from ALL sources
                                                # (mangadex, mangafire, mangakakalot) once
npm run juku -- health                          # source health check + circuit-breaker recovery
npm run juku -- proxies --check                 # health-check the proxy pool
npm run juku -- scheduler --once                # run all scheduled jobs once
npm run juku -- status                          # engine status
```

JUKU writes into the same `public/scraped.json` store the frontend reads, so
scraped content appears in the app immediately. The default source is
**MangaDex's official public API** (matches YOMIKAZE's legal content policy —
no unauthorized sites, no CAPTCHA solving, no access-control bypass).

> **Note:** the first run needs Playwright browsers. JUKU uses system Chrome
> by default (`channel: 'chrome'`); if Chrome is missing, run
> `npx playwright install chromium` once and set `JUKU_BROWSER_CHANNEL=`.

Environment variables (all optional): `JUKU_OUTPUT_FILE`, `JUKU_CONCURRENCY`,
`JUKU_TIMEOUT_MS`, `JUKU_RETRIES`, `JUKU_PROXY_FILES` (comma-separated),
`JUKU_MAX_PROXIES`, `JUKU_USE_PROXIES`, `JUKU_HEADLESS`,
`JUKU_BROWSER_CHANNEL`.

## 🧠 Caching & rate limits

- In-memory TTL cache wraps all provider calls (`src/lib/cache.ts`)
- AniList client retries 429/5xx once with backoff, then surfaces typed errors
- Search is debounced; duplicate requests are absorbed by the cache
